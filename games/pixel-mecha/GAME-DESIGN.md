# 像素机甲对战（Pixel Mecha Duel）设计说明

一个纯前端、零依赖的复古像素 1v1 机甲格斗 Demo：浏览器原生 ES Module + Canvas 2D，逻辑以 60Hz 固定步长推进，画面在 320×180 的软件像素缓冲上绘制后整数倍放大，保证像素边缘锐利。

## 1. 玩法设计

### 1.1 核心循环

两名机操控者（或一名玩家 + 一台 CPU）在一座黄昏工业平台上对峙。玩家通过移动、跳跃抢占身位，用轻斩与重斩互相削减血量，防御用于硬吃对手的必杀技并保留能量反击。每回合 60 秒，回合结束按血量百分比判定胜负；先赢 2 回合者拿下整场对局。

### 1.2 操作映射

| 动作 | 玩家 1 | 玩家 2（本地双人） |
| --- | --- | --- |
| 左右移动 | `A` / `D` | `←` / `→` |
| 跳跃 | `W` | `↑` |
| 轻斩（快、耗能低） | `J` | `1` 或 小键盘 `1` |
| 重斩（慢、耗能高、破防） | `K` | `2` 或 小键盘 `2` |
| 防御（按住） | `L` | `3` 或 小键盘 `3` |

全局按键：`M` 静音、`R` 重开一局、`P` 暂停、`V` 切换玩家 2 为 CPU 或本地双人、`C` 切换 CPU 难度。

### 1.3 数值表

机甲共有属性：最大血量 100，最大能量 100，躯干判定框 24×51 像素。

| 项目 | 轻斩 | 重斩 |
| --- | --- | --- |
| 前摇 / 判定 / 后摇（帧） | 5 / 4 / 11 | 13 / 5 / 22 |
| 伤害 | 7 | 16 |
| 攻击距离（像素） | 30 | 38 |
| 硬直帧数 | 12 | 20 |
| 击退速度 | 2.4 | 5.2 |
| 能量消耗 | 0 | 28 |
| 对防御的伤害倍率 | ×1.6 | ×2.4 |

其余规则：

- 移动速度 1.6 像素/帧，跳跃初速度 −8.2 像素/帧，重力 0.55 像素/帧²，落地可立即再次起跳。
- 防御状态下受到伤害为 20%（向上取整，最少 1 点），每次格挡消耗 8 点能量并免除击退；能量不足以格挡时防御被打破，承受全额伤害并陷入 24 帧硬直。
- 防御时能量以 0.6/帧流失，其余状态以 0.35/帧回复。长时间贴身防御会耗尽能量，这是「防御不能无脑长按」的核心压力。
- 受击后进入硬直，期间不能行动；击退以 0.86 的比例逐帧衰减。
- 竞技场宽 320 像素（单屏），角色活动范围限制在 x ∈ [28, 292]，两台机甲之间保持至少 24 像素间距，无法互相穿过。

### 1.4 回合与胜负

- 每回合 60 秒（3600 帧），倒计时归零时按剩余血量百分比判定，血量百分比相同判为平局并重打该回合。
- 一方血量归零立即进入 KO 演出（120 帧），败者播放倒地姿势、胜者播放举刃姿势，随后结算该回合胜场。
- 先取得 2 回合胜利者赢下整场对局，进入结算画面并显示胜者。
- HUD 常驻显示双方血条、能量条、倒计时与回合胜场标记（菱形）。

### 1.5 CPU 对手

CPU 采用「观察—决策—执行」三段式，每个决策间隔读取对手状态并决定本区间的意图：

- 距离大于攻击距离时向对手推进，进入攻击距离后按概率出轻斩或重斩。
- 观察到对手处于出招前摇且距离在威胁范围内时，按概率进入防御。
- 自身血量低于 30% 时提高后撤与防御倾向，自身能量充足时更倾向使用重斩。
- 出招后进入冷却，冷却期间只走位和防御，避免无限连打。

难度分三档：

| 难度 | 决策间隔（帧） | 出招冷却（帧） | 重斩概率 | 防御概率 | 失误概率 |
| --- | --- | --- | --- | --- | --- |
| EASY | 18 | 52 | 0.15 | 0.25 | 0.30 |
| NORMAL | 13 | 38 | 0.30 | 0.45 | 0.15 |
| HARD | 8 | 26 | 0.45 | 0.65 | 0.05 |

无头模拟（玩家 1 完全不操作）下，CPU 击倒玩家所需时间约为 EASY 19 秒、NORMAL 12 秒、HARD 9 秒；玩家若交替防御与反击，续航时间明显更长。

## 2. 核心代码结构

```
games/pixel-mecha/
├── index.html              页面外壳、缩放样式、操作提示
├── GAME-DESIGN.md          本文档
├── src/
│   ├── main.js             画布装配、主循环调度、输入路由、模式切换
│   ├── core/
│   │   ├── loop.js          固定步长主循环（60Hz 逻辑 + rAF 渲染）
│   │   ├── rng.js           确定性伪随机（mulberry32），保证场景可复现
│   │   ├── input.js         键盘状态机 + 边沿检测（按下/抬起/长按）
│   │   ├── audio.js         WebAudio 合成音效
│   │   └── framebuffer.js   软件像素缓冲（清屏/矩形/精灵/图块绘制）
│   ├── art/
│   │   ├── palette.js       调色板（两台机甲配色 + 场景配色）
│   │   ├── sprites.js       机甲骨架像素图 + 姿势表（纯数据）
│   │   └── scene.js         视差场景图层生成（随机但可复现）
│   ├── game/
│   │   ├── fighter.js       机甲状态机、物理、攻击判定与受击结算
│   │   ├── ai.js            CPU 行为
│   │   ├── match.js         回合流程、计时、胜负判定
│   │   └── fx.js            粒子、斩击弧、伤害飘字、屏幕震动
│   └── ui/
│       ├── font.js          3×5 像素字模
│       ├── mecha.js         机甲部件拼装绘制
│       ├── hud.js           血条、能量条、倒计时、回合标记、横幅
│       └── render.js        渲染管线（按固定顺序合成一帧）
├── shots/                   无头出图产出的核对截图
└── tools/
    └── shot.mjs             无头渲染出图（自带 PNG 编码器），用于截图核对
```

依赖方向单一向下：`main → {core, game, ui}`、`game → {core, art}`、`ui → {core, art}`。`art/` 只产出数据，`game/` 只消费数据，渲染完全由 `ui/render.js` 编排，因此美术替换只动 `art/`，玩法调整只动 `game/`。

数据流（每帧）：

1. `input.js` 汇总键盘状态 → `ai.js` 产出 CPU 输入 → 得到玩家 1 与玩家 2 的输入对象。
2. `fighter.js` 推进双方状态机（移动、跳跃、出招前摇/判定/后摇、防御、受击硬直），输出当前攻击判定框。
3. `match.js` 处理双方判定框相交、结算伤害与能量、推进回合流程（倒计时、KO、换回合）。
4. `fx.js` 根据战斗事件生成粒子、飘字、震屏。
5. `main.js` 调用 `ui/render.js` 与 `art/scene.js` 绘制到 320×180 缓冲，再由 `ImageData` 贴到画布，CSS 以整数倍放大。

渲染管线固定为：天空 → 夕阳 → 远景山脊 → 中景塔楼 → 近景桁架 → 地面 → 机甲 → 特效 → HUD → 横幅。全部为像素网格绘制，放大时关闭图像平滑。

渲染核心不依赖 DOM：所有绘制都写进一块 `Uint8ClampedArray` 像素缓冲，浏览器把它转成 `ImageData` 贴图，无头脚本则直接编码成 PNG，两者共用同一套渲染代码。

## 3. 基础素材方案

### 3.1 调色板

机甲像素图使用 10 个字符索引（`.` 透明、`0` 描边、`1` 暗部、`2` 主体、`3` 高光、`4` 强调暗部、`5` 强调亮部、`6` 辉光、`7` 钢材、`8` 刃光），两台机甲共用同一套索引、只替换颜色表，因此同一份部件数据即可生成两种涂装：

| 角色 | 名称 | 描边 | 主体 | 高光 | 强调色 | 辉光 |
| --- | --- | --- | --- | --- | --- | --- |
| 玩家 1 | 苍岚 AZURE | `#070b16` | `#37527c` | `#5f86bd` | `#41c7f5` | `#dff4ff` |
| 玩家 2 | 赤霄 EMBER | `#140608` | `#7c2f2c` | `#b55a49` | `#ff8a3c` | `#ffe2c0` |

场景使用独立的一组色板（天空渐变 6 段、夕阳、远山、中景塔楼、桁架、地面网格），与机甲色板互不影响，保证角色在任何背景上都有足够对比。

### 3.2 机甲精灵：部件拼装 + 姿势表

不采用整张位图逐帧绘制，而是把机甲拆成 6 个可复用部件，每台机甲约 51 像素高：

| 部件 | 尺寸 | 说明 |
| --- | --- | --- |
| 头 | 14×11 | 面罩发光条与头顶天线 |
| 躯干 | 20×22 | 肩甲、胸口进气口、腹部能量核心 |
| 手臂 | 7×18 | 前臂与拳部 |
| 腿 | 8×18 | 髋关节与脚部推进块 |
| 推进器 | 7×9 | 背部喷口，跳跃时高亮 |
| 能量刃 | 6×16 | 刃尖朝上，握把在下 |

躯干由左半行镜像生成（`mirrorRows`），保证左右完全对称且行宽不会写错。

姿势表按状态组织：`idle`（2 帧呼吸）、`run`（4 帧）、`jump` / `fall`（各 1 帧）、`light`（3 帧：蓄力 / 突刺 / 收势）、`heavy`（3 帧：举刃 / 下砸 / 收势）、`block`、`hurt`、`ko`、`win`（2 帧）。每帧只给出各部件的绝对位置，未列出的部件沿用基准位，因此新增一帧动画不必重画像素。`validateParts()` 在启动时校验每张部件表的行宽与行数，素材写错会立刻失败而不是画出错位的机甲。

### 3.3 场景素材

场景不用外部图片，全部按图层程序化生成（种子固定，渲染结果可复现）：

- 天空层：6 段竖直渐变 + 像素夕阳圆盘 + 稀疏星点（预烘焙成一张叠加层，避免每帧重新随机）。
- 远景层（视差 0.15）：随机游走生成的锯齿山脊剪影。
- 中景层（视差 0.35）：带天线与亮窗的工厂塔楼。
- 近景层（视差 0.6）：横梁与立柱构成的桁架。
- 地面层（视差 1.0，锁定在屏幕上）：平台、网格分割线、边缘高光与碎石。

远、中、近景三层随双方中点做小幅视差漂移，地面与机甲同深度因此锁定，保证站位与判定不会因镜头移动而错位。所有图层宽度为屏幕两倍（640），横向平铺，镜头漂移时不会露边。

### 3.4 音效

WebAudio 实时合成，无音频文件：出招是短促方波扫频，命中是噪声爆破，重斩命中叠加低频方波，格挡是高频短噪，KO 与回合开始是上行琶音。`M` 键可静音。音频上下文在首次播放时惰性创建，符合浏览器的自动播放策略。

## 4. 运行方式

```sh
# 任意静态服务器即可，无需构建、无需安装依赖
python3 -m http.server 8080 --directory games/pixel-mecha
# 浏览器打开 http://localhost:8080/
```

无头出图核对（用于验证画面而不打开浏览器）：

```sh
node games/pixel-mecha/tools/shot.mjs    # 输出 shots/*.png（3 倍放大）
```

该脚本跑一段脚本化的对局（接近 → 轻斩命中 → 防御格挡 → 重斩命中 → KO → 回合结算），并在每张截图后打印双方血量、能量与状态，便于核对数值是否与画面一致。

## 5. 扩展点

- 新增招式：在 `fighter.js` 的 `ATTACKS` 增加条目，在 `sprites.js` 增加对应姿势帧，在 `ai.js` 增加选择权重。
- 新增场景：编辑 `scene.js` 的图层函数即可，机甲与特效逻辑不受影响。
- 替换美术：保持 `sprites.js` 的部件尺寸与姿势表接口，替换像素图或颜色表即可，无需改动战斗逻辑。
- 接入网络对战：把 `match.js` 的回合推进抽到可回放的确定性步进函数，`loop.js` 的定步长设计已经满足回放与输入同步需求。
