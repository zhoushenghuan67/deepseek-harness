# 像素机甲对战（Pixel Mecha Duel）设计说明

一个纯前端、零依赖的复古像素 1v1 机甲格斗 Demo：浏览器原生 ES Module + Canvas 2D，逻辑以 60Hz 固定步长推进，画面在 320×180 的低分辨率缓冲上绘制后整数倍放大，保证像素边缘锐利。

## 1. 玩法设计

### 1.1 核心循环

两名机操控者（或一名玩家 + 一台 CPU）在一座黄昏工业平台上对峙。玩家通过移动、跳跃抢占身位，用轻斩与重斩互相削减血量，防御用于硬吃对手的必杀技并保留能量反击。每回合 60 秒，回合结束按血量百分比判定胜负；先赢 2 回合者拿下整场对局。

### 1.2 操作映射

| 动作 | 玩家 1 | 玩家 2（本地双人） |
| --- | --- | --- |
| 左右移动 | `A` / `D` | `←` / `→` |
| 跳跃 | `W` | `↑` |
| 轻斩（快、耗能低） | `J` | `1` 或 小键盘 `1` |
| 重斩（慢、耗能高、破防） | `K` | `2` 或 小键盘 `2` |
| 防御（按住） | `L` | `3` 或 小键盘 `3` |

全局按键：`M` 静音、`R` 重开一局、`P` 暂停、`V` 切换玩家 2 为 CPU 或本地双人。

### 1.3 数值表

机甲共有属性：最大血量 100，最大能量 100。

| 项目 | 轻斩 | 重斩 |
| --- | --- | --- |
| 前摇 / 判定 / 后摇（帧） | 5 / 4 / 11 | 13 / 5 / 22 |
| 伤害 | 7 | 16 |
| 攻击距离（像素） | 30 | 38 |
| 硬直帧数 | 12 | 20 |
| 击退速度 | 2.4 | 5.2 |
| 能量消耗 | 0 | 28 |
| 对防御的伤害倍率 | ×1.6 | ×2.4 |

其余规则：

- 移动速度 1.6 像素/帧，跳跃初速度 −8.2 像素/帧，重力 0.55 像素/帧²，落地可立即再次起跳。
- 防御状态下受到伤害为 20%（向上取整，最少 1 点），每次格挡消耗 12 点能量并免除击退；能量不足以格挡时防御被打破，承受全额伤害并陷入 24 帧硬直。
- 防御时能量以 0.8/帧流失，其余状态以 0.35/帧回复。
- 受击后进入硬直，期间不能行动；击退以 0.86 的比例逐帧衰减。
- 竞技场宽 320 像素（单屏），角色活动范围限制在 x ∈ [28, 292]。

### 1.4 回合与胜负

- 每回合 60 秒（3600 帧），倒计时归零时按剩余血量百分比判定，血量百分比相同判为平局并重打该回合。
- 一方血量归零立即进入 KO 演出（120 帧），随后结算该回合胜场。
- 先取得 2 回合胜利者赢下整场对局，进入结算画面并显示胜者。
- HUD 常驻显示双方血条、能量条、倒计时与回合胜场标记（◆）。

### 1.5 CPU 对手

CPU 采用「观察—决策—执行」三段式，决策间隔随难度变化：

- 距离大于攻击距离时向对手推进，进入攻击距离后按概率出轻斩或重斩。
- 观察到对手处于出招前摇且距离在威胁范围内时，按概率进入防御。
- 自身血量低于 30% 时提高后撤与防御倾向，自身能量充足时更倾向使用重斩。
- 难度分三档（简单 / 普通 / 困难），分别对应 14 / 9 / 5 帧的决策间隔与递减的失误概率。

## 2. 核心代码结构

```
games/pixel-mecha/
├── index.html              页面外壳、缩放样式、操作提示
├── GAME-DESIGN.md          本文档
├── src/
│   ├── main.js             画布装配、主循环调度、输入路由、模式切换
│   ├── core/
│   │   ├── loop.js          固定步长主循环（60Hz 逻辑 + rAF 渲染）
│   │   ├── rng.js           确定性伪随机（mulberry32），保证场景可复现
│   │   ├── input.js         键盘状态机 + 边沿检测（按下/抬起/长按）
│   │   ├── audio.js         WebAudio 合成音效
│   │   └── pixels.js        像素绘制原语（精灵、镜像、调色板映射）
│   ├── art/
│   │   ├── palette.js       调色板（两台机甲配色 + 场景配色）
│   │   ├── sprites.js       机甲部件像素图 + 姿势表（纯数据）
│   │   └── scene.js         视差场景图层生成（随机但可复现）
│   ├── game/
│   │   ├── fighter.js       机甲状态机、物理、攻击判定与受击结算
│   │   ├── ai.js            CPU 行为
│   │   ├── match.js         回合流程、计时、胜负判定
│   │   └── fx.js            粒子、斩击弧、伤害飘字、屏幕震动
│   └── ui/
│       ├── font.js          3×5 像素字模
│       └── hud.js           血条、能量条、倒计时、回合标记、横幅
└── tools/
    └── shot.mjs             无头渲染出图（Node + Canvas 垫片），用于截图核对
```

依赖方向单一向下：`main → {core, game, ui}`、`game → {core, art}`、`ui → {core, art}`。`art/` 只产出数据，`game/` 只消费数据，渲染完全由 `main.js` 编排，因此美术替换只动 `art/`，玩法调整只动 `game/`。

数据流（每帧）：

1. `input.js` 汇总键盘状态 → `ai.js` 产出 CPU 输入 → 得到玩家 1 与玩家 2 的输入对象。
2. `fighter.js` 推进双方状态机（移动、跳跃、出招前摇/判定/后摇、防御、受击硬直），输出当前攻击判定框。
3. `match.js` 处理双方判定框相交、结算伤害与能量、推进回合流程（倒计时、KO、换回合）。
4. `fx.js` 根据战斗事件生成粒子、飘字、震屏。
5. `main.js` 调用 `ui/hud.js` 与 `art/scene.js` 绘制到 320×180 缓冲，再整数倍放大到屏幕。

渲染管线固定为：清屏 → 天空 → 远景山脊 → 中景塔楼 → 近景桁架 → 地面 → 机甲 → 特效 → HUD → 横幅。场景与机甲均为像素网格绘制（逐像素 `fillRect`），放大时关闭图像平滑。

## 3. 基础素材方案

### 3.1 调色板

机甲像素图使用 10 个字符索引（`.` 透明、`0` 描边、`1` 暗部、`2` 主体、`3` 高光、`4` 强调暗部、`5` 强调亮部、`6` 辉光、`7` 钢材、`8` 刃光），两台机甲共用同一套索引、只替换颜色表，因此同一份部件数据即可生成两种涂装：

| 角色 | 名称 | 描边 | 主体 | 高光 | 强调色 | 辉光 |
| --- | --- | --- | --- | --- | --- | --- |
| 玩家 1 | 苍岚 AZURE | `#070b16` | `#37527c` | `#5f86bd` | `#41c7f5` | `#dff4ff` |
| 玩家 2 | 赤霄 EMBER | `#140608` | `#7c2f2c` | `#b55a49` | `#ff8a3c` | `#ffe2c0` |

场景使用独立的一组色板（天空渐变 6 段、夕阳、远山、中景塔楼、桁架、地面网格），与机甲色板互不影响，保证角色在任何背景上都有足够对比。

### 3.2 机甲精灵：部件拼装 + 姿势表

不采用整张位图逐帧绘制，而是把机甲拆成 6 个可复用部件（头部 10×8、躯干 14×16、手臂 5×13、腿 6×13、推进器 5×7、能量刃 4×14），每台机甲约 37 像素高、20 像素宽。每个动画帧只描述「部件相对基准位的偏移」，例如行走帧只改双腿与双臂的位移，攻击帧只改前臂与刃的位移。

姿势表按状态组织：`idle`（2 帧呼吸）、`run`（4 帧）、`jump` / `fall`（各 1 帧）、`light`（3 帧：蓄力 / 突刺 / 收势）、`heavy`（3 帧：举刃 / 下砸 / 收势）、`block`、`hurt`、`ko`、`win`（2 帧）。部件数据与姿势表是纯数据模块，可在运行时校验每行像素宽度，避免素材表错位。

### 3.3 场景素材

场景不用外部图片，全部按图层程序化生成（种子固定，渲染结果可复现）：

- 天空层：6 段竖直渐变 + 像素夕阳圆盘 + 稀疏星点。
- 远景层（视差 0.15）：随机游走生成的锯齿山脊剪影。
- 中景层（视差 0.35）：带天线与亮窗的工厂塔楼。
- 近景层（视差 0.6）：横梁与立柱构成的桁架。
- 地面层（视差 1.0）：平台、网格分割线、边缘高光与碎石。

所有图层宽度为屏幕两倍，横向平铺，保证镜头漂移时不会露边。

### 3.4 音效

WebAudio 实时合成，无音频文件：出招是短促方波扫频，命中是噪声爆破，重斩命中叠加低频方波，格挡是高频短噪，KO 与回合开始是上行琶音。`M` 键可静音。

## 4. 运行方式

```sh
# 任意静态服务器即可，无需构建、无需安装依赖
python3 -m http.server 8080 --directory games/pixel-mecha
# 浏览器打开 http://localhost:8080/
```

也可用仓库根目录的 `pnpm dsh web` 之类的宿主能力访问，但本 Demo 不依赖任何仓库包。

无头出图核对（用于验证画面而不打开浏览器）：

```sh
node games/pixel-mecha/tools/shot.mjs            # 输出 shots/*.png
```

## 5. 扩展点

- 新增招式：在 `fighter.js` 的 `ATTACKS` 增加条目，在 `sprites.js` 增加对应姿势帧，在 `ai.js` 增加选择权重。
- 新增场景：编辑 `scene.js` 的图层函数即可，机甲与特效逻辑不受影响。
- 替换美术：保持 `sprites.js` 的部件尺寸与姿势表接口，替换像素图或颜色表即可，无需改动战斗逻辑。
- 接入网络对战：把 `match.js` 的回合推进抽到可回放的确定性步进函数，`loop.js` 的定步长设计已经满足回放与输入同步需求。
